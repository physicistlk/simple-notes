## Cheap editor gaps (2026-11-05, orchestrator)
Four gaps users notice immediately, all source-manifest-clean (zero `uses-permission`, no network):

1. **Inline links.** `[label](url)` in any block. Insert via the toolbar `🔗 Link` button, the slash menu's *Link* entry, or a selection (the dialog pre-fills it). `LinkTarget.normalize` accepts only `http(s)`/`mailto` or a bare host (auto-prefixed `https://`, bare e-mail → `mailto:`), and **rejects** `javascript:`/`data:`/`file:`/`content:`/`intent:`/`android-app:` so a pasted URL can never launch from a note. `LinkTarget.open` hands `ACTION_VIEW` to another app and swallows failures. Preview styles links blue + underlined and opens them on tap (`ClickableText` + `getStringAnnotations`); the library card preview flattens `[label](url)` to `label`. Split mode wraps the raw-markdown selection instead of a block.
2. **Indent/outdent on lists.** Toolbar `⇤`/`⇥`, block menu *Indent*/*Outdent*, and hardware Tab / Shift-Tab on a focused list block. Applies only to bullet/numbered/task (the markdown grammar has no nesting for prose), clamped to `BlockStructureOps.MAX_INDENT = 6`; persisted as leading spaces by `BlockModel`.
3. **Image picker.** `ActivityResultContracts.GetContent("image/*")` — no storage permission, the URI carries a read grant. `NoteFileStore.saveNoteImage` copies into `note/<id>/img_<ts>.<ext>` and the block stores `![alt](fileName)`. `getNoteAsset` resolves only plain file names inside that note dir (`/`, `\`, `..` rejected), so content cannot escape. The editor row and the preview render local files through `BitmapUtils.loadImage` (downsampled RGB_565, 12-entry LRU); remote URLs are **never** fetched — the placeholder card stays. Export does not bundle attachments (known limitation).
4. **Block menu.** `⋮` gutter handle per row opens `BlockMenuSheet`: turn into (Text/H1–H3/bullet/numbered/task/quote), indent/outdent (lists only), move up/down, duplicate (new UUID, caret at end), copy markdown (toast distinguishes "Block copied" from "Block is empty"), delete (never leaves the editor blockless).

Conversion rules (`BlockStructureOps.textForTarget`) keep a block from re-parsing as its old type: image → alt text, table → `cell · cell` rows with separators dropped, divider → empty; text → image gets `![<cleaned text>](https://)` (valid reference, alt kept), text → table gets the default table, table → table keeps existing pipes. Nesting survives only list → list.

## 2026-11-06 addendum 6 — block references and block backlinks (schema 11)

- **Gap closed**: note-level `[[Title]]` links existed, but nothing could point at a single paragraph. Blocks have had stable UUIDs since v6, so block references no longer need a title that can be renamed.
- **Syntax**: `((shortKey))` / `((shortKey|alias))`, where `shortKey` is the first 8 hex characters of the block UUID. It is a literal prefix of the stored id, so resolution is `note_blocks.id LIKE key || '%'` — no extra column, and a reference written before its target note was ever opened starts resolving on its own.
- **Validation**: the grammar accepts only hex/dashes (`^[0-9a-f][0-9a-f-]{3,35}$`), so prose parentheses cannot turn into references and a user-supplied `%`/`_` can never reach SQL. Fenced code (whole document) and CODE blocks (per-block index) are skipped, matching tags and wiki links.
- **Index**: new `block_refs` table, one row per (source note, source block, target key), replaced wholesale per note inside `saveNoteBlocks` and backfilled by `reindexAll` for live notes only. A deleted target block does not delete the row: it becomes a "Missing block" row, the same honesty the wiki-link sheet has for renamed notes.
- **Reads**: outgoing refs resolve the key with a deterministic correlated subquery (one row per key even if two UUIDs shared an 8-char prefix — 4×10⁹ keys make that negligible) and join the live note title; backlinks join other notes' refs into any block of the open note. All three queries were run against a real SQLite database with sample data (host sqlite3), including a ref to a full UUID and a ref from a recycled note.
